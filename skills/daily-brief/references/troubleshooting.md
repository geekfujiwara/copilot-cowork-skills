# Troubleshooting

## 取得結果が空

利用者のタイムゾーン、検索期間、権限を確認する。月曜日や休暇明けは前就業日まで期間を広げる。取得できない内容を推測で補わない。

## 会議本文が空

`bodyPreview` がない場合は「詳細本文未取得」と記載し、準備内容を断定しない。

## HTML 表示が崩れる

本文形式が HTML であることを確認し、外部データを HTML エスケープする。外部スクリプトやリモート画像は埋め込まない。

## 送信できない

宛先、権限、プラットフォームの承認状態を確認する。承認を迂回せず、送信されていない場合は完了と報告しない。

## 過去の会話または台帳を取得できない

新しい会話で代替実行せず、送信を中止する。同日の送信済みメールを確認し、重複しないと確定できるまで再送しない。
初回実行であることを確認できた場合だけ `output/daily-brief-history.md` を作成する。

## 台帳と送信済みメールが一致しない

送信済みメールを配信判定に使う。送信済みで台帳にない場合は再送せず、送信内容を確認して台帳へ復旧エントリを追記する。
台帳に記録がありメール送信を確認できない場合は、自動再送せずユーザーに状態を報告する。

## ニュースの重複判定が曖昧

正規URLだけでなく、見出し、発行元、公開日、元となる発表を比較する。同じ出来事の可能性が残る場合は除外する。
実質的な更新を確認できた場合だけ、前回配信日と新しい事実を示して「続報」とする。

## セクションの一部を取得できない

取得できたセクションで処理を続け、失敗理由を本文に明記する。ただし日次重複判定、宛先確認、送信前確認が失敗した場合はメール全体を送信しない。
