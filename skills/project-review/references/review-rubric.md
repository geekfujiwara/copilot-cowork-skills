# Review Rubric

## 判定

各所見は次のいずれかに分類する。

- `強み`: 維持または拡張すべき、根拠のある設計
- `適合`: 現時点の基準を満たす
- `改善`: 成果または実現性を高める具体的な変更が必要
- `重大リスク`: 意思決定前に対処すべき高影響の問題
- `要確認`: 判断に必要な情報が不足または矛盾

総合結果を単純平均だけで決めない。重大リスク、依存関係、意思決定段階を考慮する。

## 五観点

### Alignment

目的、対象利用者、組織戦略、ポリシー、意思決定者の期待が対応しているか。目的と活動を混同していないかを確認する。

### Completeness

スコープ、非スコープ、成果物、責任者、依存関係、前提、制約、リスク、測定方法、移行・運用が揃っているかを確認する。

### Feasibility

必要能力、時間、予算、データ、技術、調達、運用、変更管理が現実的かを確認する。未確認の前提は `要確認` とする。

### Leverage

再利用可能な資産、標準、テンプレート、既存機能、成功事例の判断基準を活用しているかを確認する。表面的な模倣は推奨しない。

### Outcomes

期待成果、先行指標、結果指標、基準値、目標値、測定頻度、責任者、学習サイクルが定義されているかを確認する。

## 所見の必須項目

- 観点
- 判定
- 対象箇所
- 根拠
- 影響
- 推奨アクション
- 優先度
- 確信度
- 出典または `要確認`
