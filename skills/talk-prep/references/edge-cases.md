# talk-prep 異常系・トラブルシュート

正常系は SKILL.md。ここは例外・つまずき対処をまとめる。

## 1. 同梱アセットを前提にしない
- スキルが参照するファイル（台本テンプレ・実績一覧・顔写真フォルダ等）が**実在するとは限らない**。
- **参照前に `ls` で確認**。無ければ自力で作るか、`[要確認]` のプレースホルダーにする。
- スキル本文に「存在するかのように」書かない（過去に未配置ファイルを参照して事故）。

## 2. 大容量／添付 PPTX の取得・読み込み
- `ReadFileContent`（OneDrive/SharePoint）や Teams 添付で取得すると、バイナリは
  `grounding/downloads/` などに保存される。返り値のローカルパスを使う。
- `python-pptx` に渡すときは**絶対パス**を使う（カレントディレクトリ相対だと
  `PackageNotFoundError` になることがある）。
- 抽出はスライド単位でループし、`text_frame` と `table` の両方を拾う（`scripts/extract-deck-text.py`）。
- 巨大ファイル（数百 MB、動画埋め込み等）でもテキスト抽出は可能。重ければ枚数を分割して読む。

## 3. 素材が見つからない／読めない
- 捏造しない。`[要確認]` を残し、ユーザーに再取得・再添付を依頼。
- 一次情報（録画・RFI 本体・議事録）が必要なら、横断検索（SearchM365 / SharePoint）で拾う提案をする。

## 4. Teams / メールからの依頼抽出
- メンション（mentions）・添付（attachments[].contentUrl / name）・本文から WHO/WHAT/WHEN を読む。
- 割当時間（枠）が会話の中で変わることがある（例：「30分」→「縛りなし」）。最新の合意を採用。
- 外部ポータル（ADO/ICM 等）のリンクはアクセス不可。その旨を明示する。

## 5. 送信ガード（返信下書き）
- 返信は既定で下書き。`SendDraftMessage` / `SendEmailWithAttachments` は**ユーザーの明示指示まで呼ばない**。
- 既存の書きかけ下書きがあれば重複を知らせ、破棄要否を確認。

## 6. プロフィール・写真
- プロフィール文は記憶 `user_profile_bio.md` の確定版をそのまま使用。表記ルール厳守。
- 顔写真は、配置が確認できた場合のみ添付（パスは使用前に `ls` で確認）。新規取得は依頼時のみ。
