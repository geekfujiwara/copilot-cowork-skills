# Action Options

## 返信

返信先、スレッド、本文、添付、送信タイミングを確認する。既定では下書きに止め、送信は別に承認を得る。

## フォローアップ

誰に、何を、いつまでに確認するかを示す。既に回答済みまたは別チャネルで解決済みでないかを確認する。

## 委任

委任先、理由、必要な背景、期限を提案する。権限や担当を推測せず、利用者が選ぶ。

## 予定化

会議が必要な理由、参加候補、所要時間、期限を示す。招待作成は利用者の承認後に行い、送信前に再確認する。

## タスク化

タスク名、期限、参照リンク、完了条件を提案する。作成先と担当者を確認する。

## 保管候補

対応不要で今後の参照価値が低いことを説明する。移動、アーカイブ、削除はそれぞれ別の操作として確認する。

## 対応不要

理由を記録する。配信停止、削除、既読化まで自動的に含めない。

## 要確認

判断に不足する情報を一問で確認できる形にする。根拠のない返信案や期限を作らない。
